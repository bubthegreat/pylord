# pylord v0.1 Implementation Plan

> **Status: delivered.** Tasks 1–21 are implemented and committed. A later
> source-fidelity audit against `reference/lord.js` corrected several items
> this plan describes; where the two disagree, the code and
> `docs/deviations.md` are current. Notes below are marked where that

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Playable LORD clone: telnet server, full core game loop (town/forest/combat/shops/inn/PvP/dragon), hooked-core IGM framework, starter-six classic IGMs.

**Architecture:** Single asyncio process; one coroutine per telnet session; SQLite (WAL) persistence; hardcoded faithful engine with hook points (Other Places, forest/inn events, daily maint, mail effects) where drop-in `igms/` plugins attach.

**Tech Stack:** Python 3.12+, uv, telnetlib3, stdlib sqlite3, pytest, ruff. License GPL-3.0 (formulas ported from Synchronet `xtrn/lord/lord.js`).

## Global Constraints

- Python `>=3.12`; deps managed ONLY via uv (`uv add`, `uv run`). Runtime deps: `telnetlib3` only.
- License: GPL-3.0-or-later; SPDX header not required per-file, LICENSE file required.
- All gameplay numbers (tables, formulas) must match `reference/lord.js` (Synchronet port). When a doc value and lord.js disagree, lord.js wins. Record deviations in `docs/deviations.md`.
- Package layout per spec: `pylord/` package, `igms/` drop-in dir at repo root, `config.toml` at repo root.
- Every player mutation inside a DB transaction. IGM code never touches core tables except via `IgmContext`.
- Terminal output uses LORD backtick color codes internally; rendered to ANSI at the session boundary.
- Commit after every green test cycle. Conventional Commits format.

**Spec:** `docs/superpowers/specs/2026-07-23-pylord-design.md` — read it first.
